# 第一阶段：模型官方价格计量技术路径

状态：方案，尚未实施  
适用代码：`dsh-token-plugin` 2.0.1 工作区  
制定日期：2026-11-01（北京时间）

## 1. 目标与计价口径

第一阶段为 **DeepSeek、小米 MiMo、千问 Qwen、Kimi、智谱 GLM** 建立统一的官方价格参考计价能力。无论从哪个平台调用，先确定调用的具体模型，再采用该模型开发方官方 API 的公开按量价格和规则进行估算。

例如，硅基流动调用 `Qwen/Qwen3.6-27B`，只有在能够确认其与百炼官方 `qwen3.6-27b` 对应时，才使用百炼价格；调用 DeepSeek 也遵循相同原则。不同平台提供的同名模型不一定是同一版本，官方 API 别名发生的模型升级也不能自动推广到第三方平台。

界面和导出统一命名为**官方价参考金额**。它不代表实际平台账单：第三方价格、缓存实现、免费额度、套餐、折扣、税费和账户结算规则都可能不同。调用平台和实际模型信息仍需保留，供核对使用。

五家均为第一阶段交付范围，具体模型以各家官方公开、可核实且能与调用记录可靠对应的型号为准。没有官方价格、价格不完整、型号不明或计价所需数据缺失时，展示明确状态，不猜测单价，不把未知费用标为免费。

本阶段面向插件能够捕获的模型调用及其可获得的用量。图片、音频、视频、搜索、缓存存储等独立计费项只有在计费单位、用量和官方规则均可核实后才纳入；否则显示未覆盖，不能并入一个看似完整的总金额。

## 2. 官方来源与能力调查

| 模型开发方 | 第一阶段官方来源 | 实施前必须核验 |
| --- | --- | --- |
| DeepSeek | [模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) | 具体版本、官方别名的适用范围、北京时间峰谷与节假日、生效日期。 |
| 小米 MiMo | [MiMo API 价格](https://mimo.mi.com/docs/pricing) | 大陆与海外价格、模型版本、缓存和调用方式；优先覆盖当前配置中的 V2.6 Flash、Pro、Pro UltraSpeed。页面能否由宿主稳定读取仍需实测。 |
| Qwen | [百炼模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)、[模型列表接口](https://help.aliyun.com/zh/model-studio/list-models) | 精确型号、输入长度阶梯、思考模式、缓存类型、地域和官方来源。北京地域按量价格作为默认参考，可在设置中选择其他已支持地域。 |
| Kimi | [Kimi 模型推理价格与计费](https://platform.kimi.com/docs/pricing/chat) | 精确型号、缓存命中、缓存写入和有效期、批量与标准调用的差别；逐型号确认完整价格数据。 |
| GLM | [智谱 API 定价](https://docs.bigmodel.cn/cn/guide/start/pricing) | 精确型号、输入／输出长度分档、缓存命中及存储、价格单位；图片和音视频等非 token 计价不可套用文本公式。 |

百炼模型列表接口文档要求 API Key；北京地域端点还要求 WorkspaceId。它的结果可能包含其他厂商的模型及不同推理服务商，不能把所有返回价格当作模型开发方的官方直销价。先评估无需额外凭据的官方页面获取方式；若支持官方接口，必须使用用户已配置且用途匹配的凭据，不创建凭据，也不把凭据发往其他域名。凭据缺失不妨碍其他厂商刷新。

不同官方来源是否存在稳定的机器可读价格接口、能否读取完整峰谷和缓存规则，**尚未逐一验证**。接入时记录实际验证结果；不能因为网页可以浏览，就声称已有稳定价格 API。

## 3. 刷新、缓存与价格时效

1. 对每家官方来源独立维护最近一次**成功校验并写入**的价格数据与时间。
2. 插件启动后异步检查：没有缓存或距离该来源上次成功刷新达到 6 小时，则在后台刷新；不到 6 小时继续使用缓存，并按各来源的下次到期时间调度检查。刷新不得阻塞模型流、记录写入或面板首次打开。
3. 面板提供“立即刷新”，可刷新指定来源或全部来源。对同一来源合并并发请求；超时、限流和失败使用有上限的退避重试，不能每次模型调用都重新请求价格。
4. 请求失败时保留该来源最近一次校验成功的数据；距离上次成功超过 24 小时标记“价格可能过期”。从未获取成功或无可靠数据时标记“暂无价格”。来源间独立失败，不让一家失败清空其他家缓存。
5. 每个来源显示 `lastAttemptAt`、`lastSuccessAt`、刷新结果与来源链接；模型条目单独保存适用性和完整性，避免来源成功但部分模型缺项时误标全部有效。
6. 区分**抓取时间**和官方公布的**生效时间**。只有官方明确提供生效时间时才自动安排未来生效；无法核实时保留“生效时间未知”，不能把抓取时间伪装成官方生效时间。

峰谷判断在本地根据已校验的规则和调用时间进行，不依赖每次刷新价格。第一版以记录的调用开始时间作为参考计价时点；跨时段请求如果无法核实官方实际结算时点，应说明这是估算。节假日数据需要有来源及覆盖年份：超出已核实年份时不能静默假定不是节假日，应标注时段规则不完整。

“实时价格”在本方案中指最近一次成功获取的官方价格：正常情况下最长约 6 小时发现变化，但官方发布延迟、页面变化或网络故障会使延迟更长，不能承诺零延迟。缓存内容需校验来源、型号、币种、单位、数值、规则与时间区间；结构异常、价格缺失或解析器失配时拒绝替换上次有效数据。

## 4. 当前代码与改造边界

- `lib/index.js` 中的 `modelKeyOf`、`unitSnapshotOf` 和 `costFor` 将模型识别、服务商价格、峰谷及费用计算混在一起；目前部分分支按 `flash` / `pro` 子串匹配，未知组合返回 0。需要拆分，避免把小米 Flash 等误判为 DeepSeek Flash。
- `llm/stream` 探针当前记录请求中的 `provider`、`model`、开始时间和上游 usage。必须先核实宿主提供的字段能否取得实际路由模型、调用模式、缓存类型、TTL 和模态，再决定可支持哪些计费规则；不得假设这些字段一定存在。
- `lib/records.js` 的 `normalizeRecord` 目前仅保留固定字段和旧 `unit` 结构。直接新增快照字段会在重启或导入时丢失，必须同步扩展归一化、持久化、去重、导入导出及兼容测试。
- `projectRecord`、聚合、日历、`stat` 的版本指纹、SSE、CSV/JSON/PNG 与 `lib/client.js` 中的金额展示都依赖现有数字字段。当前存在 `|| 0` 等逻辑，必须逐个改造，保证“未知”不会被当成免费、有效金额不会被误清空。
- `PriceView` 目前主要面向 DeepSeek 固定价格，且前端注释写明不可编辑；`pricing.json` / `pricing-history.json` 是既有结构，不作为新官方来源缓存直接覆盖。保留用量面板，调整价格与来源展示。

## 5. 设计与实现步骤

### 5.1 来源适配与目录

新增独立的价格目录及各厂商来源适配层，避免继续在 `lib/index.js` 中堆叠分支。建议拆分为：

- `lib/pricing/catalog.js`：统一条目、版本和校验；
- `lib/pricing/resolver.js`：调用平台型号到官方型号的确定性映射；
- `lib/pricing/sources/`：五家官方来源的独立读取与解析；
- `lib/pricing/engine.js`：适用规则选择、金额与状态计算；
- `lib/pricing/cache.js`：分来源缓存、刷新调度与状态。

目录条目至少包含：`sourceId`、`sourceUrl`、`officialModelId`、已核实别名及其平台范围、币种、地域、计费单位、模式、分档边界、缓存规则、峰谷和节假日规则、价格、官方生效区间、抓取／校验时间、完整性。将**模型作者**与**实际调用平台**分开保存。对可证实的别名做显式、可追溯映射；不做任意前缀裁剪或模糊匹配。路由服务只在能获得实际模型且映射可靠时计价。

来源选择顺序：可用且符合官方授权与使用条件的官方结构化接口优先；否则评估官方公开页面的机器读取和解析。解析器只接收预设官方 HTTPS 域名，限制响应大小、超时和跳转目标；不因模型名或外部页面内容拼接任意 URL。仅获取价格所需信息，不上传对话内容、用量记录或其他服务商密钥。若某来源暂不具备可靠的自动更新能力，其状态显示不可用；不能把人工价格冒充实时官方价格。

### 5.2 计量引擎

建立可独立测试的纯计算入口：输入为确认后的官方型号、有效价格规则、调用时点、地域、模式、用量分桶及汇率；输出为金额明细或明确的不可计价状态。每个规则只在所需字段齐全且分桶语义明确时生效。

- 参考公式：各计费桶用量 × 对应单价的总和；单位先统一，再做币种换算。按官方规则分别处理缓存读取、写入、存储与输出，避免输入及推理 token 重复计算。
- 官方价格存在输入／输出阶梯时，用相应请求实际的 token 数选择档位；缺少准确值时不猜档位。
- 使用可复现的精度策略（如十进制定点整数或可靠的十进制库），聚合后再按展示规则舍入，避免大量小额累加偏差。
- 汇率获取与官方价格来源分离，记录原币金额、汇率、来源和日期；缺失适用汇率时人民币金额为未知，不能显示 ¥0。
- 无上游 usage 的中断调用保留调用记录并标记用量未知。DeepSeek 搜索后端估算与按次 Search / Fetch 费用分开标注，不冒充模型实测费用。

### 5.3 状态与历史快照

新记录使用版本化 `pricingSnapshot`（字段名可在实现时调整），至少保存请求型号／实际型号、映射依据、价格源、价格与规则版本、币种、地域、使用的分档和峰谷时段、抓取时间、生效时间是否已知、汇率与计算状态。规则快照随调用绑定；结束时才能确定的用量阶梯用本次调用绑定的规则计算，避免后台刷新与流式调用发生竞态。

接口中金额以 `null` 表示无法可靠计算，数值 `0` 仅表示官方价格明确免费或有效用量计算结果确为零。另带结构化状态，例如 `priced`、`stale_price`、`unknown_model`、`missing_price`、`missing_usage`、`missing_rule`、`missing_fx`，以及缺失字段和说明。部分金额与完整金额须区分，不能将缺失的分项默认设为 0 后标成完整。

历史记录默认保持现状：旧 `unit` 继续按原规则读取并标为旧口径，不自动迁移成新官方价；刷新目录不重算历史。显式回算需先提供预览、影响数量和差异，保留备份，并允许取消；缺乏历史有效价格或用量时只能标为估算／无法回算。已有 `repriceAll` 会清除快照，改造时必须禁止其无提示地破坏上述保证。

JSON 导出／导入应可往返保存新快照和状态；CSV 至少保留可读金额、币种、状态和来源，并说明无法无损重建完整规则时的限制。旧格式继续可读。价格缓存和快照写入采用现有原子写入思路，损坏或写入失败保留原文件并报告，不得静默清空历史。

### 5.4 宿主接口与界面

在现有 `/usage/api` 中增加价格状态查询和手动刷新动作，沿用 `stat` 轻量探测，不增加全量轮询。目录内容、来源状态或过期状态变化时更新相应版本指纹并通知客户端；快照记录不因目录刷新而改变。API、SSE、导出字段变更须检查旧客户端／旧数据兼容。

价格页按五家展示官方型号、价格、地域／规则、来源链接、最后成功时间与刷新结果。概览、模型明细、日历和导出统一使用“官方价参考金额”：展示已可靠计价的小计、未计价／部分估算条数与旧口径条数；不同口径不悄悄合并成完整总额。确认的免费模型可以显示 0，未知项显示“—”及原因。中英文文案保持一致。

## 6. 分阶段执行与验收

1. **来源核验与模型清单**：逐一实测五家的公开来源、数据形态、价格项和适用条件，保存可审查的脱敏测试样本；形成型号、别名、来源、规则和已知缺口清单。先覆盖已有用量记录中的五家型号及 MiMo V2.6 三款，再扩展到五家能可靠匹配的官方文本模型。
2. **基础设施与迁移**：完成统一目录、来源校验、6 小时刷新与 24 小时过期标记、分来源持久化，以及新旧记录兼容；真实源不可读时该来源明确报告不可用。
3. **五家计价适配**：逐家实现并核对单价、缓存、分档与峰谷；通过精确模型映射使第三方调用应用对应开发方官方价。
4. **面板和导入导出**：完成来源、时效、金额状态、部分合计、旧口径和手动刷新展示，验证中英界面及 CSV／JSON／PNG 一致性。
5. **端到端验收**：先运行自动测试与打包检查，再在真实 DSH 中验证模型调用 → 记录 → 价格快照 → 页面与导出；外部服务不可用时记录未完成项，不能以模拟测试声称真实链路通过。

至少覆盖以下测试：

- 五家各有成功读取、错误／缺项、价格变更和过期缓存测试；结构变化不得覆盖上次有效缓存。
- 同一确认模型由两个提供商调用使用同一官方规则；不同型号、第三方未知版本、`flash`／`pro` 同名冲突不得误映射。
- DeepSeek 峰谷起止、周末、假日、跨午夜及节假日年份缺失；未来生效价格与无生效时间分别处理。
- Qwen 地域与阶梯边界、Kimi 缓存写入 TTL、GLM 输入／输出分档、MiMo 型号区分；缺少适用字段时不得产生伪精确金额。
- 定时刷新、启动时检查、手动刷新、并发去重、单来源失败、24 小时状态变化和断网恢复；刷新不阻塞模型调用。
- 未知金额、已确认免费金额、部分金额、汇率缺失与累计小计正确区分；价格刷新不改写已冻结的历史。
- 旧数据加载、重启、新旧 JSON 导入导出、CSV 限制、原子写入失败与历史回算预览；大数据量仍保持轻量 `stat` 轮询。

建议命令：`node --test`、`npm run check`，以及针对各来源的可重复解析测试。上线前记录官方来源核对时间、实际 DSH 测试结果与未覆盖型号；发布 npm 属于单独的发布步骤。

## 7. 验收边界

第一阶段完成意味着五家均已接入并通过上述验证，而不是宣称任何未来型号或所有模态都能自动准确计价。对于尚未有可靠官方数据、官方接口需凭据、来源结构变化、价格时效未知、模型版本不明或用量缺失的情况，保留明确状态和可追溯原因。模型官方价参考金额始终不等于第三方实际账单。
